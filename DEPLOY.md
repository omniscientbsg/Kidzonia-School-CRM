# Deploying to Render

One web service serves both the API and the built UI. The client calls
`/api/...` on its own origin, so there is no CORS to configure and nothing to
rebuild when the URL changes.

## 1. Create the service

Render dashboard → **New → Blueprint** → pick this repo. `render.yaml` is read
automatically:

| | |
|---|---|
| Build | `npm ci && npm run build` |
| Start | `npm run server` |
| Health check | `/api/health` |
| Branch | `feat/phase1` |

`JWT_SECRET` is generated by Render on first deploy. Do not set it by hand and
do not commit it — the server now **refuses to start in production without it**
rather than falling back to the shared dev secret.

## 2. Keep it awake

Render's free plan sleeps a service after 15 minutes without a request; the next
visitor then waits ~50 seconds. `.github/workflows/keep-alive.yml` pings
`/api/health` every 10 minutes to prevent that.

One thing to set after the first deploy: repo **Settings → Secrets and variables
→ Actions → Variables → New repository variable**

```
RENDER_APP_URL = https://kidzonia-school-crm.onrender.com
```

Without it the workflow fails loudly instead of pinging nothing. Run it once by
hand from the Actions tab to confirm.

## 3. Before anyone relies on it

**The free plan has no persistent disk, and this app keeps its data in a file.**
Every deploy and every restart resets the database to the seed — students, fees,
tasks and uploads all revert. Fine for a demo; not fine for real use.

To fix: set `plan: starter` in `render.yaml` and uncomment the `disk:` block.
`SCHOOL_CRM_DB` and `UPLOAD_DIR` already point at `/var/data`, so nothing else
changes.

Also worth knowing:

- **750 free instance-hours a month.** Awake 24/7 is ~730 of them, so the
  keep-alive consumes almost the entire free allowance on this one service.
- **Scheduled workflows are best-effort.** GitHub delays them under load and
  disables them after 60 days of repo inactivity. For a guaranteed always-on
  service, a paid Render plan never sleeps and needs no ping at all.
- **The JSON store is single-process.** Do not scale this past one instance;
  two would each hold their own copy in memory and overwrite each other.
- **Demo logins ship in the seed** (`password` for everyone). Change them, or
  reseed, before this is reachable by anyone you did not invite.

## Local development

Unchanged — `npm start` runs the API on 4020 and Vite on 5173 with a proxy.
The production static-serving block only activates when `dist/` exists.
